# Entertainment Complex

เว็บ React สำหรับเลือกดูหนัง ทีวีสด และกีฬาสดจาก `Doowiseplay-movies.csv` และ `Doowiseplay-movies.m3u` โดยไม่มีโฆษณาในตัวผลิตภัณฑ์

## ประสบการณ์ใช้งาน

- หน้าแรกแสดงหนังที่เพิ่มใหม่ล่าสุดจากสัญญาณอัปเดตของต้นทาง
- หน้าหมวดแยกเป็นหนัง ทีวีสด และกีฬาสด พร้อมค้นหา ตัวกรอง และ pagination
- เมนู OTT แยกต่างหาก รวมหนัง ซีรีส์ และช่องสดทุกหมวดจาก playlist พร้อมค้นหาและแบ่งหน้า โดยโหลดข้อมูลเครื่องเล่นเฉพาะชุดที่กำลังดู
- หน้ารายละเอียดแสดงข้อมูลของรายการก่อนเข้าสู่เครื่องเล่น
- หน้าเครื่องเล่นรองรับ HLS, DASH และไฟล์วิดีโอผ่าน secure proxy
- เครื่องเล่นล็อกคุณภาพสูงสุดจากต้นทางตามความละเอียด, frame rate และ bitrate โดยไม่ปรับลดตามอินเทอร์เน็ตหรือขนาดหน้าจอ พร้อมแสดงความละเอียดที่เล่นจริง
- รองรับ MPEG-TS/FLV ผ่านตัวอ่านแยก และ MKV ผ่าน Matroska parser ของ Shaka experimental build; การถอดรหัสยังขึ้นกับ codec ของอุปกรณ์และสิทธิ์ที่ต้นทางให้
- URL ของทุกหน้าสามารถเปิดหรือแชร์โดยตรงได้

## เริ่มใช้งาน

```powershell
npm install
npm run build
npm start
```

จากนั้นเปิด `http://127.0.0.1:4173`

`npm run dev` และ `npm start` จะ sync catalog ก่อนเปิดเซิร์ฟเวอร์ เพื่อหมุน token ทีวีและโหลดตารางกีฬาปัจจุบัน ส่วน Vite จะ proxy `/api/sports` และ `/api/update-catalog` ไปยัง backend production จึงไม่อ่านซอร์สของ Vercel Function เป็น HLS manifest สามารถเปลี่ยนปลายทางได้ด้วย `VITE_DEV_BACKEND_ORIGIN`

## โครงสร้าง

- React + Vite สำหรับ UI แบบหลายเส้นทาง
- Express API สำหรับค้นหารายการหนัง
- Media proxy แบบ URL ลงลายเซ็นภายในโปรเซส เพื่อส่ง Referer/User-Agent ตามไฟล์เดิมและ rewrite HLS manifest
- Proxy รับเฉพาะรายการใน catalog และ resource URL ที่เซิร์ฟเวอร์สร้างลายเซ็นให้ ไม่ได้เปิดเป็น arbitrary URL proxy
- ตรวจ metadata ของทั้ง 4 แหล่งทุก 15 นาที ดาวน์โหลดเฉพาะแหล่งที่เปลี่ยน เพิ่มรายการใหม่ และตัดรายการซ้ำแบบอัตโนมัติ (ไม่ลบรายการเดิม)
- หน้า React ตรวจ version ของ catalog และอัปเดตรายการโดยไม่ต้องรีเฟรชหน้า
- ขั้นตอน sync เก็บ `recent` IDs และ `discoveredAt` เพื่อให้หน้าแรกแสดงรายการที่เพิ่งเพิ่มจากต้นทางได้จริง
- ตารางกีฬาจะแสดงเฉพาะรายการปัจจุบันและล่วงหน้า 48 ชั่วโมง พร้อมระบุ `sportsHealth` เมื่อบาง feed ต้องใช้ข้อมูลสำรอง

ข้อมูลต้นทางและสถานะการซิงก์อยู่ในโฟลเดอร์ `data/` ส่วนรหัสสมาชิกอยู่ใน `.env.local` ซึ่งถูกกันออกจาก Git แล้ว

## ตั้งค่าการซิงก์

```dotenv
DOOWISE_MEMBER_ID=รหัสสมาชิก
DOOWISE_SYNC_INTERVAL_MINUTES=15
OTT_PLAYLIST_ID=รหัสอุปกรณ์ที่ต้นทางอนุมัติสำหรับOTT
```

เซิร์ฟเวอร์ตรวจครั้งแรกทันทีที่เปิด จากนั้นตรวจซ้ำตามช่วงเวลาที่กำหนด การซิงก์ทำงานเฉพาะตอนที่ `npm start` หรือ `npm run dev` ยังเปิดอยู่

OTT ถูกอัปเดตพร้อมหนัง/ทีวี/กีฬาโดย `npm run sync:catalog` ทั้งจากปุ่มอัปเดตและทุก 15 นาทีขณะเซิร์ฟเวอร์ local เปิดอยู่ ส่วน production ใช้ GitHub Actions `.github/workflows/sync-catalog.yml` ทุก 15 นาที ต้องตั้ง repository secret `OTT_PLAYLIST_ID` ก่อนนำโค้ดขึ้น `main` สามารถรีเฟรชเฉพาะ OTT ด้วย `npm run sync:ott`

ข้อมูล OTT อยู่ใน `public/data/ott/index.json` และไฟล์ `part-*.json` เพื่อไม่รวมรายการแสนรายการเข้ากับไฟล์คลังหลัก การดึงล้มเหลวหรือได้ playlist สถานะอนุมัติจะเก็บคลังเดิมไว้ และแสดงสถานะข้อมูลล่าช้า รายการ info/debug และลิงก์กับดักของต้นทางจะไม่ถูกเปิดหรือนำเข้า ช่อง ClearKey ใช้คีย์ที่ playlist ระบุไว้ ช่องที่ขาดข้อมูลใบอนุญาตจะแสดงข้อผิดพลาดในเครื่องเล่น

การเล่น URL HTTP ของ OTT ต้องใช้ proxy Worker รุ่นที่รองรับ HTTP ซึ่งแก้ใน `worker/src/index.ts` ด้วยแล้ว และต้อง deploy Worker รุ่นนี้พร้อมการนำขึ้น production

## ตรวจสัญญาณ OTT

`npm run audit:ott -- --group "Sport MPD" --out reports/ott-audit/sport-mpd.json --direct-on-error` ตรวจทุกรายการในหมวดนั้น พร้อมสถานะ HTTP และการเปรียบเทียบกับต้นทางเมื่อ proxy ล้มเหลว สำหรับ HLS จะตรวจ manifest เต็ม ไฟล์เริ่มต้น/ท้ายรายการ และ AES key ที่ระบุใน playlist ผลตรวจไม่บันทึก URL รับชม โทเคน หรือกุญแจ DRM

HTTP 404 หมายถึงไม่พบไฟล์ ยังใช้ยืนยันว่าสัญญาณหมดอายุไม่ได้ ส่วน manifest/segment ที่ตอบสำเร็จยังไม่ยืนยันว่าเบราว์เซอร์ถอดรหัสและเล่นได้ ต้องตรวจภาพจริงเพิ่มเติม ผลตรวจรอบ 17 ตุลาคม 2026 อยู่ใน `docs/ott-playback-audit-2026-10-17.md`

นโยบายความคมชัดและขอบเขตรูปแบบไฟล์อยู่ใน `docs/player-quality.md` ถ้าต้นทางมีไฟล์เดียว ระบบเล่นไฟล์ต้นฉบับโดยไม่แปลงลดคุณภาพ การขยายภาพไม่ได้เพิ่มรายละเอียดให้ไฟล์ 240p กลายเป็น HD/4K และ codec ที่อุปกรณ์ไม่รองรับต้องแปลงที่เซิร์ฟเวอร์ก่อน
