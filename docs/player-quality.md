# คุณภาพเครื่องเล่นและรูปแบบไฟล์

เครื่องเล่นใช้คุณภาพสูงสุดจากต้นทางในทุกหน้า: หนัง ทีวี กีฬา และ OTT โดยใช้ StreamPlayer ตัวเดียวกัน ไม่ปรับลดตามความเร็วอินเทอร์เน็ต ขนาดจอ หรือการดูแบบหน้าต่างเล็ก

## การเลือกคุณภาพ

- เรียงความละเอียดตามจำนวนพิกเซล จากนั้น frame rate และ video bitrate ไม่ใช้ลำดับรายการใน manifest เป็นตัวตัดสิน
- HLS ล็อกระดับแบบ manual ก่อนโหลด segment แรก ปิดการจำกัดตามขนาดจอ/FPS และไม่ยอมสลับลงเป็นภาพระดับต่ำเมื่อโหลดระดับสูงผิดพลาด
- DASH ปิด ABR และ Network Information API ใช้ค่าสำหรับเริ่มโหลดระดับสูง จากนั้นเลือก track สูงสุดอย่างชัดเจน โดยคงภาษาเสียงเดิมเมื่อคุณภาพภาพเท่ากัน
- เพิ่มบัฟเฟอร์เป้าหมายเป็น 90 วินาที และเวลารอโหลดเป็น 120 วินาที การเชื่อมต่อช้าอาจต้องรอหรือกระตุก แต่จะไม่ลดความละเอียดเพื่อให้ลื่นขึ้น
- แสดงขนาดภาพที่ถอดรหัสจริง เช่น 1920×1080 แทนการอ้างอิงจากชื่อไฟล์หรือคำว่า 4K ในชื่อรายการ
- ไฟล์เดี่ยวเล่นด้วยคุณภาพที่มีอยู่ในไฟล์ ไม่มีการบีบอัดใหม่ ไม่มีฟิลเตอร์เพิ่มความคมปลอม

## เครื่องเล่น

| รูปแบบ | เครื่องเล่น |
| --- | --- |
| HLS | hls.js 1.7.3 |
| DASH / ClearKey | Shaka Player 5.3.0 |
| MKV | Matroska parser ใน Shaka Player 5.3.0 experimental build ซึ่งโหลดเฉพาะตอนเปิด MKV |
| MPEG-TS / FLV | mpegts.js 1.8.2 ส่งข้อมูลเข้า MSE โดยไม่เข้ารหัสวิดีโอใหม่ |
| MP4 / WebM / MOV / M4V | ตัวถอดรหัสของเบราว์เซอร์ เล่นไฟล์ต้นฉบับ |

ตรวจชนิด stream สำหรับ URL ที่ไม่มีนามสกุลและตรวจ prefix เมื่อ MIME ทั่วไปอาจระบุผิด ตัวอย่าง: ต้นทางแจ้ง video/mp4 แต่ส่ง MPEG-TS จะถูกส่งเข้าตัวอ่าน MPEG-TS แทน native MP4

## ผลยืนยัน 17 ตุลาคม 2026

ทดสอบผ่าน React player จริงด้วยไฟล์ H.264/AAC ที่สร้างเพื่อทดสอบ:

- HLS หลายระดับและ DASH หลายระดับ: จอ 390×844, จำลองการส่ง segment ที่ 1 Mbps ยังคงเล่น 1920×1080 และไม่เรียก segment ระดับต่ำ
- MP4 / MKV / MPEG-TS / FLV: ถอดรหัสภาพ 1920×1080 ได้จริง MP4 และ MKV ทดสอบ seek ไปวินาทีที่ 7 แล้วเล่นต่อได้
- DAZN Ringside: ต้นทางมี 240p ถึง 1080p; ก่อนแก้เคยเล่น 426×240 หลังแก้เล่นจริง 1920×1080
- WILLOW: เล่นจริง 1920×1080
- SportTV 2: เล่นจริง 1024×576 ซึ่งเป็นขนาดสูงสุดใน manifest ปัจจุบัน
- Tests ด้านเลือกคุณภาพ, จำแนกไฟล์, parser และ Worker รวม 21 ข้อผ่าน และ build ผ่าน

หลักฐาน browser อยู่ใน reports/ott-audit/player-quality-2026-10-17.json ซึ่งเก็บในเครื่องและไม่เผยแพร่เป็นไฟล์สาธารณะ

## ขอบเขต

การอัปเดตเครื่องเล่นไม่ได้ทำให้ไฟล์ต้นฉบับความละเอียดต่ำมีรายละเอียดเพิ่มขึ้น การเล่นยังต้องมีข้อมูลใบอนุญาตครบ ต้นทางตอบสนอง และอุปกรณ์ถอดรหัส codec นั้นได้ MKV parser เป็น experimental และทดสอบไฟล์ H.264/AAC แล้ว ไม่ได้ยืนยัน codec ทุกชนิด เช่น DTS, TrueHD, MPEG-2 หรือ HEVC บนอุปกรณ์ทุกเครื่อง

ไฟล์ที่ถอดรหัสไม่ได้ต้องใช้การ remux หรือ transcoding ที่เซิร์ฟเวอร์ซึ่งรองรับ codec นั้น ระบบเว็บและ proxy ปัจจุบันไม่ได้เข้ารหัสภาพใหม่ จึงยังรับประกันการเล่นทุกไฟล์/ทุกอุปกรณ์ไม่ได้ ส่วน native HLS บนอุปกรณ์ที่ไม่มี MSE อาจมีข้อจำกัดการเลือกระดับจากระบบของเบราว์เซอร์
